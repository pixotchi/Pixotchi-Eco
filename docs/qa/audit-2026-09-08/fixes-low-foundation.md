# Low-priority foundation revalidation

Scope: FND-09, FND-10, FND-11, FND-12 and FND-V5. FND-V6/A2 are covered in the social report. This record describes code and bounded component evidence; final integrated results are recorded separately.

| ID | Revalidated gap | Change and reason |
| --- | --- | --- |
| FND-09 | `stickyFooter` only emitted an unused attribute; `auto` was exactly `center`. Frame and surface inline styles were indistinguishable in the public API. | Removed the inert prop and sole Casino caller; default mobile mode is explicitly center. `DialogFooter`/form layout remain the single footer policy. Added `surfaceStyle` beside documented frame `style`, preserving existing callers. Form/detail/game scroll ownership remains unchanged. |
| FND-10 | Four status wrappers accepted DOM attributes but dropped them; disabled slotted links could invoke their own handlers and navigate. | Forward compatible attributes, keep polite status defaults with explicit overrides, correctly omit native `title` from the result heading prop. Disabled/loading slotted children guard both child and wrapper handlers, including keyboard/middle-click, while retaining Tab exit. Enabled Slot composition is preserved. |
| FND-11 | CoreProviders still duplicated the theme list; eight background values were copied into JavaScript; chrome updates waited 450ms. Font aliases obscured the actual three static weights; headings wrapped at line-height 1. | All providers use `THEME_NAMES`. One root observer derives chrome from the applied CSS palette immediately, also covering standalone routes. Palette copying and delay removed. Three honest font weights and documented title/label/body/secondary/numeric roles replace ambiguous hierarchy; CardTitle and DialogTitle use wrapping line height. |
| FND-12 | Card/StandardContainer/Dialog borders and surfaces drifted; broad follow/header selectors affected unrelated elements; feature styling, selection geometry and Base artwork had duplicate owners. | Card and StandardContainer share a panel role; dialog uses edge tokens. Lifted surfaces now have semantic names with their verified contextual ink unchanged. Feature CSS moved to named style files, card dealing to a CSS module, identity-kit to explicit integration classes, and generic header positioning to the app header only. Tabs/radios share geometry and keyboard indexing while retaining separate semantics. Base artwork/palette/color lifecycle share one implementation that pauses when hidden; see the Base report. |
| FND-V5 | Nested content panels and raised inactive groups flattened hierarchy. | Added flat task panels, borderless supporting insets and spacing-only groups. Economy/Activity/Ranking now apply these roles to real content; radio group wrappers are quiet while the active pill remains distinct. See economy/social evidence for actual screens. |

Additional original foundation observations addressed within the same shared pass: remote avatar image failures render a stable generated fallback; unknown radio values paint no false selection; exact-amount disclosures have a 44px minimum hit height; automatic transaction feedback adopts the 1280px desktop navigation boundary. These are not extra counted audit groups.

Final enlarged-text review also corrected header/theme-choice clipping, Wallet Profile scroll starvation and Switch geometry drift. The active, opt-in `adaptiveScroll` API preserves mounted content and one scroll owner through reflow; shared close/header chrome remains 44px. See [header/CSS review](review-feature-css-and-header.md) and [final wallet layout](fixes-final-wallet-layout.md) for the original reproductions, scoped fixes, screenshots and limits. This API has measured behavior and tests, unlike the inert option removed under FND-09.

`tests/frontend/foundation-low.spec.ts` exercises child/parent activation, Tab exit, DOM/ARIA forwarding, immediate all-eight-theme chrome, actual surface parity, doubled-text wrapping, one-scroll-body footer reachability, invalid/keyboard/resized selections and failed image loading. Independent review reproduced a new ResizeObserver initial-delivery animation cancellation, corrected it, and added a normal-motion test for initial delivery, smooth retargeting, keyboard immediacy and reduced-motion cancellation. This test passes Chromium and WebKit. Disabled/enabled Link sequences also passed six independent repeats; Next hash navigation is asynchronous and the assertion now awaits its completion.

Focused checks initially exposed test timing errors: the enabled Link assertion read the URL before Next completed navigation, and a lazy avatar had not requested its failed image. The corrected tests await navigation and require an observed failed image request before accepting the fallback. These earlier attempts are not counted as final release passes.

The shared [presentation contract](../frontend-design-contract.md) documents future component use. Exact final counts, visual references, release isolation and remaining physical/host acceptance belong to the coordinating low-round report. No physical touch keyboard, screen reader, Mini App host or universal state coverage is claimed here.
