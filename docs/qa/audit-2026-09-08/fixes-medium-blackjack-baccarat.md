## Contract-derived Baccarat details

Read-only resolution of the configured Base Diamond’s baccaratGetActiveGame selector identified facet **0xdaf996ef01dc1a387187d85b23d9dfc8c9a7c97c**. Its [verified source](https://basescan.org/address/0xdaf996ef01dc1a387187d85b23d9dfc8c9a7c97c#code) defines MAX_REVEAL_DELAY = 256, requires current block > revealBlock and expires only when current block > revealBlock + 256. The last deadline block is therefore still valid. Commission is bounded at 10,000 basis points; Tie profit multiplier is 1–20. The local evidence copy is output/baccarat-facet.html.

The interface uses exact block counts rather than claiming a fixed real-time countdown. Block progression and wallet latency vary. Other games supply their own verified window to the helper.

## Material limits and preserved boundaries

The current Blackjack read ABI supplies a base bet and cards, but omits historical per-hand Double stakes. An observed round keeps exact committed accounting. A resumed split on hand 2 can have an unknown prior Double; its display explicitly says “At least … committed,” explains the missing stake history and suppresses an exact net amount. Recovering the exact historical total requires an additional canonical event-history/read contract, not guessed arithmetic. Existing deployed Blackjack action/view facets were unverified on Basescan during this review, so no claim of independently verified Blackjack contract source is made.

Browser fixtures prove deterministic application behavior, not physical iOS/Android wallet webviews, real wallet approval latency, screen-reader speech output or production contract execution. The screenshots use fixture tokens and a deterministic font. New/additional wagers require verified token metadata/config/balance; no-new-spend Hit/Stand/Surrender/Reveal and durable recovery stay available. Results never substitute guessed decimals or zero for unavailable receipt data.
