# ARC-06 final coverage register — 2026-09-08

**ARC-06 remains partially addressed and open for release acceptance.** The original requirement was reproducible player journeys and explicit state/device coverage, not a larger fixture pass total. The current tree adds a real-provider journey, production-component/controller regressions, real-style layout checks and CI gates. It does not establish complete seeded gameplay, external-wallet handoff or physical-device acceptance.

This register compares the [original ARC-06 finding](architecture.md), [coverage remediation record](fixes-coverage.md), current test/configuration sources and recorded results. The final real-provider app checkpoint has **six passes** after the Mint and Activity corrections. Build, release isolation, post-build TypeScript and the recorded source/domain checks passed. The primary fixture matrix retains **3,767 passed, 110 skipped, one failed and zero flaky**, across 3,878 combinations; its test-only failure correction and later production changes have separate passing verification below. No full matrix on the final patched tree is claimed. Earlier domain reports retain their checkpoint scope. This update only reads existing local evidence and edits this document; it runs no tests, external requests or device sessions.

Evidence classes used below:

- **R — real provider/app:** actual app login, providers, shell, UI and live reads. The bounded Local Test Wallet journey makes no paid submission; real shell visibility is not proof that the rendered feature completed its business flow.
- **C — controlled production code:** actual production components, hooks or installed SDKs, with specified wallet/RPC/HTTP/signature/execution boundaries replaced or intercepted. This proves the asserted behavior under those inputs, including deterministic races. It does not prove live provider, service or contract integration.
- **V — presentation:** compiled app styles and production presentation, screenshots, geometry, keyboard or text/motion emulation. Some older behavior harnesses use minimal CSS; only the explicitly styled checks support visual conclusions.
- **S — smoke/source contract:** local parsers, state policies, receipt/proof logic, cache contracts or structural checks. These supplement browser journeys; they do not substitute for a wallet round trip.
