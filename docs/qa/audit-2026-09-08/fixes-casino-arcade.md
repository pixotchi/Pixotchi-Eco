## Verified SpinLeaf contract window

The original audit's expiry formula stopped at commit + 257. Revalidation found that this discarded the last valid contract block and corrected it.

The proxy's live `getImplementationForFunction(spinGameV2Play(uint256,bytes32))` returned `0xF7E86A862B395313eF685F6A11E2287D5b898f81`. The saved primary bytecode artifact at `docs/research/plant-economy-2026-09-05/sources/SpinGameV2.json` exactly matched `eth_getCode(latest)` during this work. Keccak-256: `0x9ba07b210956cb19d6d5cb2686d95e789d8b13ea91b8f17640cd64044d10e1ee`.

Independent bytecode inspection by the building-panel owner verified the deployed conditions: at 0x15e7 the stored commit block becomes randomness block `commit + 1`; the comparison at 0x160a requires `current > randomnessBlock`; at 0x1658/0x1665 the limit is `current <= randomnessBlock + 256`. Thus reveal is valid from commit + 2 through commit + 257 inclusive; commit + 258 is expired. The UI gives urgent final-block copy. A future transaction is never guaranteed to be included before expiry: the fresh read and simulation validate current eligibility, not future inclusion. The current extension source is unverified on BaseScan; these semantics were checked against deployed bytecode, not guessed from an empty source file.

The reproducible read-only disassembly/live-comparison helper is `output/inspect-spin-expiry.mjs`. It does not submit transactions. No wallet transactions were submitted by this implementation subtask.
