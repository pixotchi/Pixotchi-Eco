## Final pass: controller boundaries and push readiness

- **Transaction monitoring:** the submitted-batch monitor and abortable wait/handoff behavior now live in a small tested module. A UI timeout retains the original wallet status promise; retries request status, never another submission. Timers/listeners are cleaned up. Transaction-kit callbacks accept unknown errors and capabilities instead of any. Existing durable proof, ownership, deadline and lease authorities remain in place.
- **Swap:** one quote hook owns debouncing, bounded transport retries, idle refresh, explicit refresh and draft/wallet/visibility scoping. Late responses cannot restore an obsolete quote, and hidden panels cancel reads while retaining the amount. Quote and build responses validate token/amount/route shapes and the Base network. The single-leg build API always labels a returned leg step1; the adapter correctly restores a requested step2 after matching economic identity. Batch responses use the shared validator and every reported hash receives a canonical receipt check.
- **Swap amount layout:** token selectors now sit beside Sell/Buy labels, leaving the entire next row for amounts. Type scales to the actual card width with a 16px minimum, including the narrower tablet column. Ordinary values and an 18-decimal input fit at 320/390/864/1440px; unusually long editable inputs retain native horizontal editing and receive amounts can wrap.
- **Barracks:** a land-scoped snapshot hook owns block refresh and receipt-triggered reloads. V1/V2 configuration, troop, state, report and preview normalizers moved to a pure module and reject missing/malformed fields rather than inventing false/zero values. Eligible-target read failures now reach the existing Retry UI. A complete zero-ID report remains a real empty state.
- **Ranking:** Stake and Rocks now have separate query controllers and strict API parsers. Both observers share each request; errors cannot become zero rows. Rocks caches its disabled notice with the response, so tab revisits retain the explanation. Attack event parsing is shared, checks the emitter, and uses the typed lifecycle for pending/rejection handling; duplicate Kill/Revive failure toasts were removed.
- **Casino/Arcade:** Blackjack receipt decoding is isolated and typed, including card/deal/hit/split/result data and split payouts. A result-only receipt now supplies its outcome even without GameComplete; duplicate logs cannot double a payout. Decoding ignores other emitters and rejects unknown result enums. SpinLeaf metadata and commits are validated against the player, plant and sealed block. Box rewards are decoded from the correct plant/contract; missing reward evidence no longer displays an invented zero reward.
- **Chat:** public/AI history is parsed before it enters presentation state, conversation IDs are checked, and optimistic messages are merged by a tested helper. The composer and message presenter remain separate from authentication/stream orchestration. Lifecycle/error callbacks in the changed ranking, swap, Blackjack and Arcade paths have concrete types.
- **QA enforcement:** real swap, Barracks and ranking controllers now have browser race/error/Retry fixtures. Encoded ABI event tests and interrupted monitor tests complement the browser suite. Every one of the 32 production DialogContent call sites has a named regression suite and an explicit explanation of the remaining provider/service boundary. An AST-based inventory check fails when call-site coverage decisions drift. The workflow runs on beta/dev pushes and PRs, with source/build/release isolation, the browser matrix and Windows visual comparison jobs.

## Shared component contracts

- **Card:** root owns padding; Header and Content do not add horizontal padding. Use `padding="none"` when a region explicitly owns its own spacing. `surface="raised"` remains a restrained content surface rather than a second modal layer.
- **DialogContent:** `padding="default"`, `"compact"` or `"none"` controls `--dialog-padding`; shared Header/Footer derive offsets from it. Preserve the existing focus restoration, feedback portal, safe areas and visual-viewport height cap. `none` is for self-contained custom layouts, not a reason to omit content spacing.
- **Dialog layout:** `form` = nonshrinking Header/Footer with scrolling Body (Footer sticky by default); `detail` = nonshrinking Header and scrolling Body; `game` = whole-surface scrolling with nonshrinking children and optional sticky game chrome. `custom` keeps existing feature scroll ownership. Size and padding are independent choices; use `size="sm"` for a small confirmation. Do not override the viewport cap. `GameDialogHeading` delegates to the feature's existing close guard.
- **AmountField:** owns visible label/unit, associated description/error, optional available balance and an external Max control. Callers own domain parsing, affordability and submission. `maxLabel` distinguishes actions sharing a unit, such as two troop types. Disable Max when a trustworthy balance is unavailable.
- **Token display:** bigint arithmetic throughout summary formatting; two fractional digits for common compact summaries; nonzero sub-precision amounts are visibly nonzero. Use exact units for editable amounts and final trade/care review. A displayed summary is never an affordability check.
- **TokenAmount / duration:** summary text retains the exact amount in its title and accessible label. Estimates are visibly marked; exact review amounts wrap. Editable values use ungrouped exact units. Durations use total days, with at most two nonzero units in compact displays and all units in exact results.
- **Quest query:** owner, read-chain ID and land ID form the key. No previous-key placeholder data. Failed queries hide stale action slots. The overview owns periodic refresh; detail observes that cache and performs bounded post-receipt reconciliation. The app reads Base state; query fixtures additionally verify chain-key isolation.
- **AssetMultiSelect / ApprovalState:** selection is controlled by the feature and begins empty; the selector only counts current holdings, never selects new items automatically and gives each collection a distinct label. Approval read states are information; only `required` renders the supplied transaction component. Ownership, allowance reads and durable recovery remain feature responsibilities.
- **ResourceState:** loading, error and empty presentations are distinct. Retry repeats a guarded read; it must not manufacture an empty success. Domain controllers retain ownership and request-generation checks.
- **GameTransaction:** shared success text is captured when the operation starts so later form clearing does not rewrite it. Use `successFeedback="feature"` only where the feature owns the result presentation; pending/errors/recovery remain shared. Standalone approval steps keep their own shared confirmation.
- **Dialog focus:** a single shared pointer/keyboard tracker identifies Safari pointer openers. A registry routes an early nested Escape to the focused dialog and honors its `preventDefault`; normal Radix dismissal, focus scopes and feedback portals remain in use.
